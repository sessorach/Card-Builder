# CLAUDE.md: working notes for Card Builder

## Start of every session
1. Read this file and `DESIGN.md` before doing anything else.
2. If anything the user says contradicts either file, point it out and ask; don't silently pick one.

## Record-keeping rules (from the user)
- Keep two running records and maintain them without being asked:
  - `CLAUDE.md` (this file): practical working notes: where things live, how to build and test, settled conventions, past mistakes and how to avoid them. Fix or remove anything stale.
  - `DESIGN.md`: the project's decision record for human readers, in plain prose: what was decided, why, alternatives rejected, and standing rules. No workflow notes there.
- When the user makes a decision, corrects me, or explains their reasoning, record it in the right file **in the same commit** as the related change, never as a later catch-up.
- Commit and push doc updates along with the work.
- **Commit messages:** short, general summaries of the kind of work ("Layout work: colors and title font", "Font testing", "Art matching improvements"). No layout-specific details such as stat names, type names or color values. Keep the attribution trailers.
- **README:** a concise how-to for people using the site. No change notes, no development or process details, no per-layout column lists (the column list in the page's Templates & examples tab has those). Outward-facing text stays short; detail goes in DESIGN.md.

## What this is
Repo: `sessorach/Card-Builder` on GitHub (public, default branch `main`). GitHub Pages is on and deploys `main`. A static web page: drop a spreadsheet + art → preview cards → download a zip of card PNGs, or a zip containing a Tabletop Simulator Saved Object (the primary use). No build step, no framework, no server.

## Where things live
- `index.html`, `css/style.css`: the page. Sidebar = three steps only (Your files: one `.file-row[data-drop]` per input with a status line and a Tips `<details>`; Look; Download). Everything else is a tab in `.main`: `cards`, `data`, `tts`, `start` (Templates & examples). `showTab(name)` in main.js switches them; any `[data-tab-link]` button opens a tab. Keep extra links and explanations out of the sidebar's flow (DESIGN.md, "The page"). The TTS tab's guidance: Steam Cloud steps (`#tts-cloud`, an `ol.guide`), then "Put the deck into TTS" (`#tts-load`, visible; the page scrolls there after a TTS download), then a collapsible "If something goes wrong" (`#tts-help`). Elements switch per option with `[data-help-mode="cloud local web"]` (space-separated list) and fill in the user's folder or URL via `[data-fill]` (wired in `setupControls` in main.js). Keep them consistent with `instructions()` in js/export.js (`HOW TO IMPORT.txt`), the status/reason messages in main.js (`ttsLocation`, `runExport`, which refer to the step numbers) and the README. User-facing wording says "pictures", one action per line; the user prefers simple and longer over short and terse.
- `js/main.js`: UI wiring and state (inputs, preview, export buttons, localStorage settings). `renderData` builds the Data tab table and `renderArtStatus` the art row's status, both on every `rerender`. `setStatus` writes to every `[data-status]` element (sidebar and TTS tab).
- `js/spreadsheet.js`: CSV/TSV parser, header aliases, rows → cards, grouping by deck. Pure, Node-tested.
- `js/xlsx.js`: minimal .xlsx reader (JSZip + DOMParser). Browser-only; covered by e2e.
- `js/richtext.js`: text markup (`**bold**`, `*italic*`, `{icon}`, `\n`), word wrap, shrink-to-fit, TTS BBCode. Pure; measuring is injected.
- `js/render.js`: canvas renderer, `AssetStore` (images by file name or loosely by card name), `findArt` (art column → card name fallback), `cardAccent` (color column → layout `colorBy` → default), generated backs. It must stay importable in Node (no DOM use at module top level) so these helpers stay unit-tested in `tests/unit/render.test.mjs`.
- `js/textures.js`: procedural surface textures for rects and letterboxed images (`paper`, `grit`), from seeded noise tiles, so renders are deterministic. Browser-only at call time but importable in Node (no top-level DOM).
- `js/fonts.js`: font library (Google Fonts specs + faces to preload), `DEFAULT_FONTS`, and `loadFonts()`, which injects the card-fonts stylesheet. `index.html` only links the UI font.
- `js/template.js`: blank CSV templates derived from a layout's elements (`templateColumns`, `templateCsv`). Columns a layout shows with `list: true` get a `(separate with commas)` header note; `normalizeHeader` in spreadsheet.js strips any `(…)` so notes are harmless. Pure, Node-tested (`tests/unit/template.test.mjs` pins the Street and Default column lists, so update those when a layout's fields change). The Templates & examples tab lists a download per layout (`[data-template=id]`).
- `js/tts.js`: sheet planning, image URLs, Saved Object JSON. Pure, Node-tested.
- `js/export.js`: builds the zips. Browser-only. `prepareTtsImages` renders and hashes every sheet and back once; `cloudFiles` lists the unique images to upload (deduped by hash); `buildUploadZip` is the Steam Cloud upload pack; `buildTtsZip({ prepared, location })` writes the decks (cloud mode: pasted links, no image files); `buildImagesZip` is the plain card-images download.
- Steam Cloud state in main.js: `state.cloudPack` (`{ token, quality, prepared, files }`) is stale once `renderToken` or the sheet resolution changes; pasted links are stored by content hash in localStorage under `card-builder:cloud-links` and refill automatically. `ttsLocation()` returns the reason the TTS button is disabled.
- `js/sizes.js`: card sizes (poker only for now) and DPI.
- `layouts/*.js` + `layouts/index.js`: layout definitions and their registry: `default` (formerly `classic`), `full-art`, `text-only`, `street` (the user's game; Thug stats are `strengf`, `helf`, `steal`, spelled exactly so; Bling's `equip_cost` is a single centered stat box shown with `$`), `allies` (working name; draft; Ally and Action variants, `ALLY_ONLY`/`ACTION_ONLY` = `unlessHas`/`whenHas` type Action; Actions get `attackRow()` (to_hit/damage/crit/w) under the art when any is set and Range/Usage badges in the bottom corners; aura-blended background; top to bottom name, art, Immunities then Resistances as full-width strips (`strip`; positions per case via `when`/`whenAll`/`unlessAll`), ability text box (fills whatever is left above the type line), type line, then Armor badge / aura chips (`itemChips`) / Health badge; name bar, type line and text box are translucent `rgba` fills so the blend shows through), `flagonquest` (FlagonQuest companion cards, techniques and items in one layout: a row with `category` is an item, others are techniques, switched with `when`/`unless: 'category'`; reads `scripts/techniques.csv` / `scripts/items.csv` from the user's `sessorach/flagonquest` repo unchanged; `aliases` keeps the old ids `flagonquest-technique`/`flagonquest-item` working). It mirrors the site's read-only Character Sheet tiles (`TechCard` and `InventoryTile` in the site's index.html) inside Card Builder's gold card frame; the top of `layouts/flagonquest.js` maps each site constant/component to the layout part that copies it. To resync: clone the site (see Gotchas), diff those components, update the layout, and re-render `fq-*.png` from the e2e run.
- `examples/`: `example-cards.csv` (Default/Full Art/Text Only; uses an `art` column for some cards) and `street-cards.csv` (Street; no art column, every image is matched by card name). `examples/manifest.json` maps each example CSV to `{ layout?, images: [...] }`: the images it loads (a new example image must be added there) and the layout to select first (needed for examples without a `layout` column). `allies.csv` (decks Allies and Actions) shows each aura case (one color, weighted pair, Inverted, single Inverted, all four, none) and each action shape (full attack row, attack with a missing stat, no attack row, no range); its art comes from the same script. `flagonquest-techniques.csv` / `flagonquest-items.csv` are real rows copied from FlagonQuest's spreadsheets with their original headers, to prove the drop-in. Example art comes from `tools/make-example-art.py` (deterministic; needs Pillow; file names follow the cards; append new palettes at the end so existing images don't change).
- `js/handoff.js`: cards sent in the link, `#import=<base64url(deflate-raw(JSON))>` with JSON `{ v: 1, title?, layout?, columns: [...], rows: [[...]] }` (`encodeHandoff`, `handoffData`, `decodeHandoff`; Node-tested). main.js `loadHandoff` runs at start-up and on `hashchange`, then `applyRows` (shared with dropped spreadsheets). The FlagonQuest site's Character Sheet is the sender: its export must keep producing this format and these column names (see the comment at the top of `layouts/flagonquest.js` for the three columns only it fills: `built_features`, `picks`, `powers`). Bump `v` only for an incompatible change, and keep reading v1.
- `js/blend.js`: weighted color blends (`parseBlend` reads "Instinct 2, Inverted Passion" against a layout's `colors`/`modifiers`; `paintBlend` fills an RGBA buffer in one of `BLEND_STYLES` with each part's exact share of the area via `quantileThresholds`; patterns seeded by `hashSeed(card.name)`). Pure; Node-tested. render.js's `blend` element paints it at a third of the size and scales up.
- `vendor/jszip.min.js`: vendored JSZip 3.10.1 (from the npm tarball).
- `tests/unit/*.test.mjs` (node:test), `tests/e2e/run.mjs` (Playwright), `tests/fixtures/*.xlsx`.

## Run and test
- Serve: `npm run serve` (python http.server on :8000). ES modules **don't load from file://**; always serve over http.
- Unit tests: `npm test`.
- E2E: `npm run test:e2e`. It starts its own static server, drives Chromium, and checks both zips. Screenshots and downloads go to `test-output/` (gitignored). After visual changes, look at `preview.png`, `lightbox.png`, `fire-sheet.jpg`, `preview-street.png` and `street-*.png` (full-size Street cards, one per example card: two Thugs with stats, a Bling with an equip cost, and one of each other type). For FlagonQuest, `fq-*.png` (techniques) and `fq-item-*.png` (items). No example card has partial stats any more (faded slots), so check that case by hand if the stat row changes.
- E2E steps share one page and run in order: the layout-selector step expects the Default example (8 cards) to be loaded, so steps that load other spreadsheets go after it.
- E2E: the Allies step checks pixel colors at the card edge (pure Instinct is green, single Inverted is near black); look at `allies-*.png` after changing the blend or the layout.
- E2E: the last step opens the page with an `#import=` link built by `encodeHandoff` (a built technique, a picked technique, a custom item with a power) and saves `sent-*.png`; then it changes only the hash (the "send again" case) and tries a damaged link.
- E2E and tabs: Playwright can't click hidden elements, so switch tabs first (`tab(page, 'tts')` before TTS controls; `loadExample(page, file)` opens Templates & examples). Loading a spreadsheet jumps back to Cards unless Data is open. Also screenshots `start.png`, `data.png`, `templates.png` and `steam-cloud.png` (TTS tab).
- In the cloud container: `PLAYWRIGHT_SKIP_BROWSER_DOWNLOAD=1 npm install` first; Chromium is preinstalled at /opt/pw-browsers and Playwright 1.56.1 matches it.
- CI (`.github/workflows/test.yml`) runs unit + e2e tests on every push; keep both green before pushing.

## Layout format (quick reference)
Layout files are JS modules, so they can use helper functions and constants to build elements (see `layouts/street.js`, which generates its with-stats and no-stats variants from one function).
Top-level: `id`, `name`, `description`, `defaultColor`, `elements`, optional `aliases: [old ids]` (renamed layouts; `getLayout` resolves them), optional `matchColumns: [...]` (a spreadsheet with all these columns and no `layout` column switches to this layout on load; a list of lists means any one set matches, see `matchesColumns` in layouts/index.js), optional `hover: [field | { field, label, italic, bold, hideZero }]` (exact TTS hover text instead of the generic description), optional `colorBy: { field, colors: { value: color } }` (case-insensitive value → accent; a card's `color` column still wins), and optional `fonts`: role → `{ font: <FONT_LIBRARY key>, weight, boldWeight }`. Roles default to `title` = cinzel and `body` = crimson; layouts may add roles (Street adds `cost`, `label` and `stat`).
Elements are drawn in order. `x/y/w/h` are % of card width/height; `size`, `minSize`, `radius` and `strokeWidth` are % of card **width**.
- `rect`: `fill`, `stroke`, `strokeWidth`, `radius`, `texture` (`'paper'` for light panels, `'grit'` for colored/dark ones), `textureStrength` (default 1), `bevel` (`true` or a width in % of card width).
- `blend`: a background of weighted colors from a list column: `field`, `colors: { word: color }`, `modifiers: { word: { saturate, darken, mix, amount, mottle } }` (a word in an item changes that part's color; `mottle` adds dark veins through its share), `style` (default `gradient`; also `split`, `tie-dye`, `marble`, `solid`) or `styleField` (a column naming it per card), `fallback` color, `radius`, `texture`.
- `image`: `field` (default `art`), `radius`, `stroke`. Finds the file named in `field`, else an image named after the card; otherwise draws a placeholder. `fit: 'contain'` shows the whole image (letterboxed) over `background` + optional `texture`; the default crops to fill (cover).
- `text` content, one of:
  - `text: 'LABEL'` (fixed text)
  - `field` (plus `prefix`/`suffix`, added only if the value doesn't already have it; `list: true` + `listSep` splits a comma/semicolon/pipe-separated cell)
  - `join: [...]` + `sep` (+ `sepColor`): inline on one line
  - `parts: [...]`: paragraphs with a gap between them; a paragraph can be an inline group `{ join: [...], sep }`
  - `join`/`parts` entries (and a text element itself) are a field name or `{ field, bold, italic, color, prefix, suffix, label, labelColor, labelBold, list, listSep, exclude, itemColors, chip }`, or a nested inline group `{ join: [...], sep, sepColor, color, chip }` (a separator takes the group's color unless `sepColor` is set). `chip: { fill, stroke }` draws the value in a small rounded badge (each item, for a `list`; the whole group, for a `join`); chips never wrap inside (richtext.js `chipLayout`, `CHIP_PAD`). `label` puts a bold "Label:" before the value, only when there is a value (`labelSep` replaces the ":", e.g. `''` for "Physical Resist +2"). `signed` shows plain numbers as "+1"/"−1"; `hideZero` skips a 0. `exclude` drops list items; `itemColors: { Item: color }` colors individual list items; `itemChips: { words: { fill, stroke, color } }` styles a list chip by words in the item (a key matches when all its words are present, e.g. `'inverted passion'`; first matching key wins, so list combinations first).
  - `join` + `unique: true` drops an entry whose value repeats the previous one (level range "1–1" → "1").
- `text` style: `font` (role), `size`, `minSize` (shrink floor), `lineHeight`, `align`, `valign`, `baseline` (em offset, default 0.32; caps-only fonts like Bebas look centered at ~0.36), `color`, `weight: 'bold'`, `italic`, `outline` + `outlineWidth` (em, default 0.12), `shadow` (`true` for a soft glow, or `{ color, x, y, blur }` in ems), `shrink: false`.
- Any element: `when` / `unless` (a field, or a list of fields meaning "any of them has a value"), `whenAll` / `unlessAll` (a list: all of them have values), `whenHas` / `unlessHas: { field, value }` (a list cell like tags contains value, case-insensitive; `value` can be a list, meaning any of them), `opacity`, `rotate` (degrees, around the element's center).
- Color tokens: `accent`, `accentDark`, `accentLight`, `onAccent` (black or white, whichever reads on the accent), `ink`, `paper`, `paperLight`. Accent comes from the card's `color` column, else the layout's `defaultColor`. Any CSS color string also works.

## Conventions
- Keep game-specific knowledge out of `render.js` (see DESIGN.md's standing rule). New designs go in `layouts/`.
- Pure logic goes in Node-testable modules with no DOM; add unit tests for it.
- New third-party code is vendored into `vendor/` (with its license), never loaded from a CDN at runtime. Google Fonts is the only external load.
- Problems with user input become warnings in the UI, not exceptions.
- Columns keep one meaning across layouts; formatting (like Street's `$` cost) belongs in the layout via `prefix`/`suffix`, never in the data or the renderer. Shared columns so far: name, count, deck, layout, art, cost, type, subtype, tags, text, flavor, stats, strengf, helf, steal, equip_cost, color, plus FlagonQuest's level_min, level_max, action, condition, target, special, choice_effects, prereqs (techniques) and level, category, slot, accuracy, damage, range, relevant_skills, weapon_defense, might_requirement, held_slots, the resist/defense/speed/health bonus columns, value_per_level, main_materials, material_types (items), Allies' aura, armor, health, resists, immunities, to_hit, crit, w (header alias "[W]"), usage (plus the shared damage and range) and blend (any layout can use `blend` for a blend style), and built_features, picks, powers (filled only by the FlagonQuest site's character export). Header aliases map "Effects" → text and "Description (Fluff)" → flavor (`normalizeHeader` checks the full header, parentheses included, before stripping notes).
- TTS hover descriptions (`cardDescription` in js/tts.js) list any column not in its `DESCRIBED` set as "Label value", so new stat columns need no TTS changes. A new column that *shouldn't* appear on hover must be added to `DESCRIBED`.
- Renaming a layout id breaks spreadsheets that name it in their `layout` column (they fall back to the default, with a warning). Mention it to the user when it happens.

## Gotchas and past mistakes
- `node --test tests/unit/` treats the directory as a file on Node 22; use the quoted glob in `package.json`.
- `package.json` has `"type": "module"`, so `require('vendor/jszip.min.js')` doesn't return JSZip in Node. The UMD build registers `globalThis.JSZip` instead (see `tests/e2e/run.mjs`).
- cdn.sheetjs.com and cdnjs are blocked from the cloud container; the npm registry works (`npm pack <pkg>` to fetch a tarball for vendoring).
- The Claude GitHub App can't create repositories (403); the user has to create them.
- TTS caches images by URL, so sheet file names must keep their timestamp.
- Local-mode image paths (`imageUrl`/`localImagesFolder` in js/tts.js): Windows → plain path `C:\…\Card Builder\images\x.jpg` (per TTS docs, untested in TTS); Linux/Mac → `file:///home/…` with raw spaces. Tested by the user on native Linux TTS: plain `/home/…` → "WWW Image Error: Cannot connect to destination host" (treated as a URL); `file:///` raw and `%20`-encoded both → "Load image failed unsupported format: UNKNOWN". Working theory: the files weren't where the deck pointed (unzip nesting). Open question until the user confirms; don't flip the format again without new evidence from TTS.
- The user plays TTS on **Linux** (Saved Objects at `~/.local/share/Tabletop Simulator/Saves/Saved Objects`) and is on UTC−7. Exported file names carry the browser's *local* download time (`deck-YYYYMMDD-HHMMSS-…`), so compare that against commit times (UTC) to tell which version of the site a reported download came from. GitHub Pages caches for ~10 minutes; a hard refresh gets the newest version.
- To pin down TTS behavior without running TTS, send the user a small test Saved Object with one card per variant (e.g. path styles), each image saying which variant it is, and ask which ones show. The scripts for the path test live only in the session scratchpad; rebuild from this description if needed.
- Steam Cloud flow wording follows TTS's official knowledge base (source: github.com/Berserk-Games/Tabletop-Simulator-Knowledge-Base, `docs/custom-content/cloud-manager.md`; kb.tabletopsimulator.com doesn't resolve from the container but raw.githubusercontent.com does): **Upload → Cloud Manager**; the folder icon to the *left* of its search bar uploads one file; clicking an asset copies its URL. "Some versions call it Modding" (in the troubleshooting list) is from forum posts. Not seen first-hand: if the user reports different menu names, update `index.html` (`#tts-cloud`, `#tts-help`) and `instructions()` in export.js.
- The e2e Steam Cloud step reloads the page to prove remembered links refill. Anything that changes the images between the two passes (like the uploaded back, which a reload clears) must be redone after the reload, or the hashes won't match.
- The FlagonQuest site (`sessorach/flagonquest`, public; clone read-only with `GIT_LFS_SKIP_SMUDGE=1 git clone --depth 1 https://github.com/sessorach/flagonquest`) loads React/Babel from unpkg, which the container can't reach. To screenshot it, `npm pack` the same packages into the scratchpad and serve them through Playwright `page.route`. Its palette lives in the `TEXT` constant in its index.html.
- To test the FlagonQuest site's "Make cards" button end to end: serve a clone of the site through Playwright `context.route` (React/ReactDOM/Babel/qrcode from `npm pack` tarballs in place of unpkg; Google Fonts and jsdelivr stubbed), route `https://sessorach.github.io/Card-Builder/*` to this checkout, seed `localStorage` with a character (`flagonquest-characters`, `flagonquest-active-character`, `flagonquest-char-<id>`), open `?tab=sheet`, click "Make cards" and catch the new page. The script lives only in the session scratchpad; rebuild from this description. Babel there turns `const` into `var`, so site code that runs at load can't use a constant defined further down `index.html` (it's `undefined`, not an error you'd expect).
- Adding `sessorach/flagonquest` to a session with push access needs the user's explicit approval in chat (auto mode refuses it otherwise). The site's own CLAUDE.md applies there: work on a feature branch, merge to `main` only when asked (a fast-forward), one README changelog entry per day.
- I can't run TTS in the container. Anything about TTS behavior is from docs and forum reports; say so when it matters, and ask the user for exact error text.
- Canvas only draws fonts that have already loaded; `loadFonts()` (js/fonts.js) preloads every face listed in `FONT_LIBRARY`. A new font, or a new weight/italic of an existing one, needs its face added there, or it silently renders in the fallback font.
- To compare fonts quickly, render an HTML sample page with Playwright (scratchpad) rather than editing layouts back and forth. The library already holds the display faces compared for Street (rubik-wet-paint, rubik-spray-paint, rubik-dirt, knewave, bungee-shade, lacquer), so swapping between them is one word.
- Street must never crop art (`fit: 'contain'`). To check fit after layout changes, render cards with red-bordered very tall and very wide test images (a scratch Playwright script) and confirm all four red edges show.
- Text in a box shrinks to fit its *height* too (size × lineHeight), so a big single number needs `lineHeight` < 1 or a taller box, or it silently renders smaller than `size`. Drippy/tall display fonts also need `baseline` tuned so they clear labels above and the box edge below.
- `AssetStore.add` lets a later file with the same name replace an earlier one (re-dropping fixed art must take effect).
